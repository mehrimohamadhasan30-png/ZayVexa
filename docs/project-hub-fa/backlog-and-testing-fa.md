# کارهای باقی‌مانده، ریسک‌ها و آزمایش‌های ZayVexa

این فهرست زنده است. علامت‌نزدن یک کار به معنی انجام‌نشدن یا تأییدنشدن آن است؛ هر مورد فقط پس از مشاهدهٔ شواهد واقعی تکمیل شود.

## اولویت صفر — محافظت از داده و نظم کار

- [ ] هر تغییر معنادار در مخزن و تاریخچهٔ Git ثبت شود.
- [ ] برای تغییرات بزرگ شاخهٔ جدا و Pull Request ساخته شود.
- [ ] وضعیت هر بخش و شواهد آزمایش ثبت شود.
- [ ] فایل‌های محرمانه، رمزها، توکن‌ها و اطلاعات اتصال خصوصی وارد مخزن عمومی نشوند.

## اولویت یک — بررسی و اصلاح لابی

- [ ] بررسی همهٔ دستورهای `build.mcfunction` از نظر نحو و ترتیب اجرا.
- [ ] بررسی ابعاد تمام دستورهای `fill` و محدودیت حجم هر دستور.
- [ ] بررسی هم‌پوشانی ساختمان‌ها، مسیرها، کف و ورودی‌ها.
- [ ] اصلاح محل شروع: بررسی قبلی نشان داده بود مختصات پیشنهادی `0 81 0` با بلوک‌های مرکز تداخل احتمالی دارد؛ این مورد هنوز با اجرای بازی تأیید یا اصلاح نشده است.
- [ ] بررسی امن‌بودن فضای تنفس بازیکن، کف، ارتفاع و مسیر خروج.
- [ ] بررسی اینکه راهنمای لابی با نسخهٔ واقعی فایل‌ها یکسان باشد.
- [ ] آزمایش در یک دنیای تازهٔ Minecraft Java 1.20.1.
- [ ] ثبت نتیجه با نسخهٔ بازی، خروجی خطاها و تصاویر/شواهد در صورت دسترسی.

## اولویت دو — معماری و انتخاب پلاگین‌ها

- [ ] انتخاب نسخهٔ دقیق Paper و Velocity برای Minecraft 1.20.1.
- [ ] بررسی نیاز Java و سازگاری هر مؤلفه.
- [ ] تعیین راهکار مجوزها و تنظیمات امن forwarding پروکسی.
- [ ] انتخاب و آزمایش روش اقتصاد مشترک بین سرورها.
- [ ] مقایسهٔ پلاگین‌های آمادهٔ فروشگاه مرکزی و بازار بازیکنان.
- [ ] آزمایش خرید، فروش، مالیات/کارمزد در صورت نیاز، و ذخیرهٔ پایدار موجودی.
- [ ] بررسی پشتیبانی از آیتم‌های سفارشی Slimefun و جلوگیری از تکثیر یا دورزدن قیمت‌ها.
- [ ] تعیین فهرست نهایی افزونه‌های Slimefun، با منبع و نسخهٔ مشخص.
- [ ] تأیید Placeholderهای اسکوربورد و TAB؛ هر Placeholder باید از افزونهٔ نصب‌شده پشتیبانی شود.
- [ ] بررسی GriefPrevention، حدود ادعا، پیام‌ها و مجوزها.

| ریسک | شدت اولیه | راهکار |

| Datapack هنوز در بازی اجرا نشده | بالا | آزمایش در دنیای تازه و ثبت نتیجه |

## معیارهای آماده‌بودن برای انتشار آزمایشی

- خطای بحرانی شناخته‌شده در لابی یا راه‌اندازی باقی نمانده باشد.
- انتقال بین سرورها و مجوزها آزمایش شده باشند.
- خریدوفروش آیتم‌های معمولی و Slimefun در سناریوهای اصلی و سوءاستفاده بررسی شده باشد.
- داده‌های اقتصاد و بازیکنان پس از راه‌اندازی مجدد باقی بمانند.
- نسخهٔ پشتیبان و بازگردانی آن عملاً آزمایش شده باشند.
- مستندات با فایل‌های واقعی مخزن همگام باشند.
- موارد آزمایش‌نشده صریحاً فهرست شده باشند.

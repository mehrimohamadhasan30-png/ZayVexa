## قانون نگهداری اطلاعات

هر داده، تصمیم، طراحی، نتیجهٔ آزمایش یا تغییر معنادار باید در فایل مناسب این مخزن ثبت و با Git نسخه‌بندی شود. برای هر تغییر مهم، پیام commit روشن و در صورت نیاز شاخه و Pull Request جداگانه ساخته شود.

هر مورد باید با یکی از وضعیت‌های زیر توصیف شود: **پیشنهادی، برنامه‌ریزی‌شده، پیاده‌سازی‌شده، آزمایش‌شده، تأییدشده**. «وجود فایل» به معنی «آزمایش‌شدن» یا «آمادهٔ انتشار بودن» نیست.

## دامنه و محدودیت

این پوشه بر پایهٔ اطلاعات موجود در مخزن و گفت‌وگوهای پروژه تهیه شده است. موارد قدیمی یا متناقض عمداً به‌عنوان نیازمند بازبینی علامت خورده‌اند؛ هیچ مقدار نامعلوم نباید حدس زده شود. این مستندات به‌خودی‌خود به معنی نصب نرم‌افزار، تغییر دستگاه یا اجرای سرور نیستند.
